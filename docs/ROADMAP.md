# 学习路线图

本路线图以 Refactoring.Guru 收录的 22 个经典设计模式为主线，按照创建型、结构型、行为型组织。
分类保持稳定，分类内部按由易到难的顺序推进；完成单个模式的基础练习后，再进入多模式组合实践。

每个模式都依次经历三个阶段：

1. **概念理解**：掌握模式要解决的问题、结构、适用边界和设计原则。
2. **代码实现**：参考主线网站示例完成可运行的基础实现，并用自动化测试验证关键行为。
3. **体验总结**：结合实现过程形成自己的使用感受、取舍判断和项目经验。

语言实现是学习的重要组成部分，但不是最终目的。学习进度以能否理解、实践并作出设计判断为准。

## 状态说明

### 学习状态

- `⬜ 待学习`：尚未开始。
- `🟡 学习中`：正在阅读、练习或复盘。
- `✅ 已完成`：概念理解、可运行示例与关键行为测试、体验总结三个阶段均已完成。
- `🔁 待复习`：已经完成首轮，但需要重新练习或补充理解。

### 语言实现状态

- `—`：当前没有实现计划或尚未开始。
- `🚧`：正在实现。
- `✅`：实现、测试和运行说明均已完成。

学习状态与语言实现状态相互独立。理解一个模式不要求所有语言同时实现；新增语言也可以只选择部分模式。
问题代码和完整重构过程属于可选进阶练习，不是所有模式的完成条件。

代码按照“模式 → 语言”组织。每个模式目录集中管理公共概念和学习总结，只为已经开始实现的语言创建子目录。

阶段完成条件：

- 每个模式都完成概念理解、可运行示例、关键行为测试和体验总结，并能说明代码角色与模式概念的对应关系。
- 能够区分工厂方法与抽象工厂，并说明生成器和普通构造函数的适用边界。
- 能够解释单例的全局状态、并发和测试风险，而不是只记住实现写法。
- 至少用 C# 完成全部创建型练习；其他语言按需增加。

## 第四阶段：组合与迁移

完成 22 个基础练习后，通过小型业务场景练习多个模式的协作，并比较不同语言的表达方式。

建议主题：

- 订单处理：责任链、策略、状态、命令和观察者。
- 文档编辑器：命令、备忘录、组合和访问者。
- 跨平台组件：抽象工厂、桥接、适配器和外观。
- 可扩展通知系统：工厂方法、装饰、策略和观察者。

组合练习需要明确每个模式解决的独立问题，并保留不使用该模式时的替代方案，避免为了增加模式数量而制造复杂度。

## 新增语言的记录方式

新增语言时，在各阶段表格末尾增加对应语言列，并在实际开始的模式目录下创建该语言子目录。不需要为其他模式
创建空目录，也不需要复制或清空现有语言的状态。

新增实现应回答：

- 该语言是否已经内置了模式所需的抽象能力？
- 经典面向对象结构是否仍然是惯用写法？
- 与已有实现相比，哪些差异来自类型系统、运行时或标准库？
- 简化结构后，模式的意图和取舍是否仍然清晰？
