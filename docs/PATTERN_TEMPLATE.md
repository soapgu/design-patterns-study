## 第一阶段：概念理解

本阶段先建立不依赖具体语言的理解。完成后，应当能够不用代码解释模式解决了什么问题、为什么这样设计，
以及什么时候不应使用它。

### 一句话理解

用一两句话概括模式要解决的问题及其核心做法。不要直接复制资料中的定义。

### 意图

- 这个模式试图解决什么问题？
- 它希望哪些部分保持稳定，哪些部分可以变化？
- 它带来的主要价值是什么？

### 问题场景

描述一个足以暴露设计问题的具体场景，包括：

- 当前需求和约束。
- 问题代码出现了什么坏味道或变化压力。
- 如果继续使用当前设计，下一项需求会造成什么影响。
- 为什么简单修改可能已经不够，或者为什么简单方案其实仍然更合适。

## 第三阶段：体验总结

本阶段记录亲自实现和使用后的认识。重点是形成自己的判断，不追求与参考资料得出相同措辞。

### 实现体验

- 从问题代码重构到模式实现时，最明显的变化是什么？
- 哪部分变得更容易理解、扩展或测试？
- 哪部分变得更间接、更难追踪或更难调试？
- 模式带来的复杂度是否符合最初预期？
- 哪个设计决策只有写完代码后才真正理解？

### 取舍复盘

完成练习后回答：

1. 这里是否真的需要该模式？不用它最简单的实现是什么？
2. 模式解决的是当前问题，还是只为假设中的未来需求做准备？
3. 当前语言能否通过函数、类型系统、标准库或框架能力简化实现？
4. 模式引入的复杂度是否小于它消除的复杂度？
5. 在实际项目中见过哪些相同或相反的案例？
6. 如果重新实现一次，会保留或改变哪些决策？

### 个人总结

记录自己的理解、仍有疑问的地方，以及下次复习时需要重点验证的内容。
