# 设计模式学习与实践

这是一个用于系统学习设计模式的长期练习仓库。项目以
[Refactoring.Guru 设计模式](https://refactoringguru.cn/design-patterns) 为主要学习资料，
先理解模式概念和用法，再通过代码练习验证理解，最后沉淀亲自使用后的体验与判断。

模式的概念、意图和适用边界是学习的灵魂，具体语言的项目实现是承载和验证理解的血肉。代码形式可以因语言
而不同，但模式背后的设计原则应保持一致。仓库不会把设计模式当成必须套用的代码模板；学习重点是识别模式
要解决的问题、理解它带来的权衡，并判断在具体语言和场景中是否存在更简单的方案。

## 适合人群

- 希望系统学习 GoF 经典设计模式的开发者。
- 已经接触过模式，但希望通过练习建立实际判断能力的开发者。
- 希望比较同一模式在不同编程语言中表达差异的开发者。

## 学习原则

每个模式按照“概念理解 → 代码实现 → 体验总结”的顺序形成学习闭环：

1. **概念理解**：先弄清意图、问题场景、参与者、结构、适用条件、模式关系和设计原则，能够不用代码解释模式。
2. **代码实现**：参考主线网站的基础示例完成实现，以自动化测试验证关键行为；问题代码和重构对比作为可选进阶练习。
3. **体验总结**：记录实现过程中的直观感受，分析收益、成本、替代方案、过度设计风险和真实项目用法。

代码完成不等于模式学会。只有能够说明“为什么使用、何时不该使用、使用后有什么感受”，才算完成一次学习。

## 学习范围

项目以 Refactoring.Guru 收录的 22 个经典模式为主线。

### 创建型模式（Creational Patterns）

- 工厂方法（Factory Method）
- 抽象工厂（Abstract Factory）
- 生成器（Builder）
- 原型（Prototype）
- 单例（Singleton）

### 结构型模式（Structural Patterns）

- 适配器（Adapter）
- 桥接（Bridge）
- 组合（Composite）
- 装饰（Decorator）
- 外观（Facade）
- 享元（Flyweight）
- 代理（Proxy）

### 行为模式（Behavioral Patterns）

- 责任链（Chain of Responsibility）
- 命令（Command）
- 迭代器（Iterator）
- 中介者（Mediator）
- 备忘录（Memento）
- 观察者（Observer）
- 状态（State）
- 策略（Strategy）
- 模板方法（Template Method）
- 访问者（Visitor）

具体顺序和进度参见[学习路线图](docs/ROADMAP.md)。

## 语言计划与目录约定

C# 是首个实践语言，TypeScript 和运行于 Node.js 的原生 JavaScript 是当前扩展语言。它们只是当前计划，不是仓库支持语言的限制；
未来可以根据模式特点和学习需要增加 Java、Python、Go、Rust 等语言。

目录按照“模式 → 语言”组织。每个模式集中保存概念笔记、来源、不同语言实现和体验总结：

```text
design-patterns-study/
└── patterns/
    ├── creational/
    │   └── factory-method/
    │       ├── README.md
    │       ├── csharp/
    │       │   ├── src/
    │       │   └── tests/
    │       ├── typescript/
    │       │   ├── src/
    │       │   └── tests/
    │       ├── javascript/
    │       │   ├── src/
    │       │   └── tests/
    │       └── <language>/
    ├── structural/
    └── behavioral/
```

模式目录中的 `README.md` 统一承载概念理解、示例来源、代码角色对应和体验总结；语言子目录只保存该语言的
代码、测试及必要的语言特有说明。语言目录按需创建，没有实现时不保留空目录。

每个模式应能够单独运行和测试。仓库根目录可以提供 C# 解决方案、TypeScript workspace 等统一入口，以便
批量构建分散在各模式下的同语言项目。新增语言不要求一次补齐全部模式，同一模式也不要求所有语言同步完成。

跨语言练习用于比较表达方式和语言特性，而不是逐行翻译。例如，TypeScript 实现会特别关注函数、闭包、
联合类型和结构化类型能否简化经典面向对象实现。

## 第三方示例说明

基础代码练习会参考或使用 Refactoring.Guru 对应语言的公开示例，目的仅限个人、非商业学习。每个示例目录
必须在说明文档中标注原始页面、Refactoring.Guru、获取日期、使用方式，以及原样参考和本仓库新增内容的
边界。本仓库新增的自动化测试与修改内容应和第三方示例明确区分。

Refactoring.Guru 的[内容使用政策](https://refactoringguru.cn/content-usage-policy)允许在标注来源链接并满足
其限制时免费使用部分内容，但没有为完整示例代码单独声明常见的开源许可证。因此：

- 不删除原示例已有的版权或来源信息。
- 不把许可状态不明的第三方示例重新声明为本仓库自己的开源代码。
- 将来添加仓库许可证时，应明确排除这部分第三方内容。
- 如果网站政策发生变化、权利方提出限制或仓库用途扩大，应停止使用相关内容，改为独立实现或申请授权。

## 参与方式

新增或完善一个模式时：

1. 从[模式学习模板](docs/PATTERN_TEMPLATE.md)复制一份模式说明。
2. 先完成概念理解，再参考对应网站示例完成基础实现并记录来源。
3. 为模式的关键行为编写自动化测试；只在需要深入体验时增加问题代码和重构对比。
4. 写下亲自实现后的体验、取舍和适用边界，而不只是复述资料结论。
5. 在[学习路线图](docs/ROADMAP.md)中更新学习状态和对应语言的实现状态。
6. 检查示例可以独立运行、文档链接有效，且三阶段内容均已完成。
